# 0.6.2 版本记录：真机三处修复——字幕叠字、成片静默失声、anim_get 覆没

> 三个修复都来自 2026-09-25 前后的真机会话（含宿主升到 **dsh 0.1.7-rc.2** 的兼容体检）：两个是 0.6.1 体检方法的延续（拿真实成片回执说话），一个是 0.1.7-rc.2 收紧校验引发的兼容破坏。全部修复并冒烟回归。

## 1. 修复

### F1 字幕叠字——expandNarration 反重叠钳制（真机 55/59 份回执命中）

**现象**：成片里两条字幕同时可见、文字叠文字。

**根因**（回执统计实证）：0.5.0 起字幕显示时长取「估算与实测语音的**较大者**」（宁可字比声先消失），但取大者后的时长本就可能越过下一条 cue 的起点——语音实测比估算长时尤甚。真机一份 59 条回执的会话里 55 条命中，两条字幕同屏，渲染端画在同一位置，直接叠字。

**修复**（`packages/render-mc/src/codegen.ts`）：展开后的 cue 按 `atMs` 排序（乱序输入也稳），每条终点**钳到下一条 cue 的起点**——宁可字幕早收，不叠。`displayMs` 仍按原始 cue 序号对齐（取大者在排序前完成，再参与钳制）；跨幕各出一份、30ms 尾巴不生成等既有规则不变。**CODEGEN_VERSION 7→8**：同输入下字幕时段变了，段缓存里的旧段必须失效，首次渲染自然退回全量（属预期）。冒烟新增回归断言（乱序输入 + displayMs 对齐两条路径）。

### F2 成片静默失声——Windows rename EPERM 指数退避重试

**现象**：真机渲染明明合成了配音，成片却是无声版，回执里只有一条降级警告。

**根因**（真机 2026-09-25 实证 EPERM）：`muxAudioTracks` 写临时 mp4 后 `renameSync` 一次性改名。Windows 上目标若正被占用——典型是**杀软对新落盘 mp4 的扫描锁**——改名即抛 EPERM；mux 层的容错口径是「音轨合成失败只降级警告、成片保留无声版本」（绝不让已完成的画面渲染白跑，adapter.ts:298 注释即此红线），于是瞬时扫描锁让有声成片**静默**降级为无声版。

**修复**（`packages/render-mc/src/adapter.ts`）：`renameWithRetries` 指数退避重试（9 次，250ms 起、4s 封顶）——扫描锁通常秒级释放；重试耗尽仍失败才放行原错误，走既有降级警告路径，只是不再被瞬时锁误伤。

### F3 anim_get 全军覆没——presentationMeta 无损清洗（dsh 0.1.7-rc.2 兼容破坏）

**现象**（真机事故，2026-09-25）：宿主升 0.1.7-rc.2 后 `anim_get` 全军覆没，模型全程读不到 spec。

**根因**：0.1.7-rc.2 对 `output.presentationMeta` 做无损 JSON 校验：含 `undefined` 值字段的对象判死**整个工具输出**（`ToolOutputError: presentationMeta returned non-lossless JSON`）。而 anim_get 的 presentationMeta 按 `value.path ?? undefined` 直取字段，读摘要/整份时 path/view/durationMs 皆 undefined——一个未设防的字段毒死整个工具。

**修复**（`packages/tools/src/register.ts`）：注册层统一收口，所有工具的 `presentationMeta` 过一道递归无损清洗（剔除 `undefined` 字段）。单个工具写漏防御也不再致命，后续新工具同样免疫。

## 3. 兼容口径变化

- 已验证矩阵从 0.1.7-alpha.1 扩到 **0.1.7-rc.2**；peer 依赖维持 `>=0.1.5-rc.2` 不变。
- **CODEGEN_VERSION 7→8**：0.6.1 及以前产生的段缓存对 0.6.2 全部失效一次，首次渲染退回全量，属预期行为（旧段字幕时段与 0.6.2 语义不一致，复用反而错）。
- presentationMeta 全工具无损化：回执元数据不再出现 `undefined` 字段（JSON 序列化后本就丢弃，语义不变），对旧宿主无感。
