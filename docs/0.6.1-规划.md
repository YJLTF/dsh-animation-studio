# 0.6.1 版本记录：dsh 0.1.7-alpha.1 真机体检与兼容修复

> 0.6.0 台账把「dsh 新 alpha 持续发布」挂成长期账（0.6.0 §1.1 #5：每个新版本跑挂载冒烟 + 真机体检，破坏性变更记档）。本版本就是这笔账的第一次兑现：宿主升到 **dsh 0.1.7-alpha.1** 后，用真实会话（「视频」工作区「二叉树教程演示视频制作」，60 秒成片、53 张动画卡片、4 个后台任务）做全量真机体检，抓到 1 个 0.1.7 DOM 结构变更引发的兼容破坏 + 2 个体检连带暴露的自身健壮性缺口，全部修复并真机回归。

## 1. 体检发现与根因

### F1 抽帧缩略图灯箱被困在折叠盒里（dsh 0.1.7 兼容破坏，用户报障）

**现象**：点击 `anim_preview` 卡的缩略图，灯箱没有全屏弹出，而是被困在工具调用手风琴的内部滚动盒里（360px 高）：无全屏暗色遮罩、上下带渐隐白边、翻页/关闭按钮被截断，页面其余部分照常可交互——「模态」完全失效。

**根因**（真机 DOM 实证）：dsh 0.1.7 把每回合的工具调用收进手风琴（`O_Ebla_*`），展开态的滚动体（`O_Ebla_body`）带 **`O_Ebla_fadeTop/Bottom` 渐隐 mask**（`linear-gradient` mask，滚动边缘淡出的装饰）；折叠态再叠 `content-visibility: hidden`。按 CSS 规范，祖先的 `mask` 会成为 `position: fixed` 后代的**包含块**并裁剪其绘制——灯箱的 `position: fixed; inset: 0` 从「相对视口」退化为「相对这个 360px 的盒子」，mask 再把超出部分抹掉。0.1.6 及以前的手风琴没有这层 mask，灯箱一直正常，属典型的宿主样式演进破坏。

**修复**（`packages/client/src/cards/primitives.tsx`）：灯箱从 `div position:fixed` 改为 **`<dialog>.showModal()` 顶层渲染**。top layer 高于一切祖先的裁剪（overflow/clip/mask）、包含块（transform/contain/content-visibility）与层叠上下文，是唯一不依赖宿主 DOM 结构假设的逃逸方式——此后宿主再怎么改卡片容器样式都打不到它。配套：Esc 关闭由 dialog 原生 `cancel` 事件承担（`preventDefault` + 同步 React 状态后卸载）；点背景关闭、左右翻页键、`zIndex` 9999（top layer 下已无意义，移除）语义不变；零新增依赖（不引 react-dom portal，保持对宿主 react 种子模块的版本解耦）。

### F2 自定义导出目录的拼贴图 404（自身健壮性，0.5.0 起即存在）

**现象**：渲染完成卡没有「全片关键帧拼贴图」（0.5.0 §3.3 的功能整个消失）；直接请求媒体路由返回 404「媒体不存在或不在可服务范围内」。该会话把成片导出到 `E:\个人资料\视频\`（outputDir 之外），同目录的 MP4 能播、拼贴图不能。

**根因**（代码实证 + 磁盘比对）：`indexMediaFromResult` 只登记回执里的 `outputPath` 和 `frames[].path` 进媒体索引，**漏了 0.5.0 新增的 `contactSheet` 与 `clip.path`**（单幕直放段视频）。媒体路由的放行规则是「outputDir 内 OR 工具回执里出现过」，拼贴图落在 outputDir 外又不进索引，必 404；卡片 `onError` 静默隐藏整张拼贴图，功能无声消失。

**修复**（`register.ts`）：`indexMediaFromResult` 补齐 `contactSheet` 与 `clip.path` 两类产物路径，白名单语义（「工具产出过才可服务」）不变。

### F3 宿主重启后后台卡片退化成假运行态（体检连带发现，设计缺口）

**现象**（重启宿主复验 F2 时暴露）：重启后旧会话里「渲染完成 / 渲染已终止 / 预览帧 ×N」的后台票据卡全部退化成「排队/启动中…」的**永久假运行态**，且任务簿一旦回放错账还会**跨会话串账**（二叉树的渲染卡轮询到排序会话的任务，拼贴图显示成别家的片）。

**根因**：渲染任务簿（`RenderTracker`）与媒体索引同为进程内存态。0.6.0 M3 的设计口径是「重启清空属设计内行为，卡片降级为不可达提示」——但真机回归证明这个降级口径站不住：卡片轮询 `/api/job` 拿到 404（可达但无账）时显示的不是「不可达」而是「排队/启动中…」，旧会话从此躺在假运行态里误导人。而 sidecar 事件流（`anim/render-start/progress/finished`、`anim/preview-start/finished`）与任务簿数据同源——「事件溯源 + 会话恢复」本来就该覆盖它。

**修复**（`web.ts` + `register.ts` + `index.ts` + client）：
- **挂载回放**：`replaySidecarEvents(sessionsDir, { tracker, media })` 在插件挂载时扫全部 sidecar 事件文件，灌回任务簿与媒体索引（回放后仍 `running` 的任务如实落为 `failed`，error 说明「宿主重启时任务未完成」——进程死亡即任务死亡，不伪装在线）；坏行容错跳过，扫描失败不拖垮挂载。0.6.0 §2.2 遗留账 #2 的「渲染簿持久化」以此收账：不引持久层，用既有事件流零成本回放。
- **分簿记账**：任务簿键从裸 `jobId` 改为「会话 :: jobId」（`RenderTracker.observe` 增可选 `sessionKey`，工具 emit 用当次 `agent.session.id`、sidecar 回放用文件名派生，两边同用 `safeName` 归一）。`/api/job` 增 `&session=` 参数，卡片轮询（`useJobPolling` → `fetchRenderStatus`）用回执里既有的 `sessionId` 精确对号；缺 session 的旧调用取最近一条兜底，smoke/host 冒烟等无会话环境行为不变。jobId（anim-render-1 之类）只在会话内唯一，live 并发与回放都会撞号——分簿是正解，不是回放特有的补丁。

## 3. 明确不做 / 挂账

- **spec 状态的挂载回放**：任务簿与媒体索引回放了，spec store 维持「按会话懒恢复」不变（工具调用时 fold）。总览页在重启后到首次工具调用之间 specs 列表为空，属既有设计（spec id 跨会话可能重名，挂载回放需要先解决归并与恢复顺序，收益只是总览页早几屏有内容，挂账观察）。
- **手风琴折叠时 flowItem 的 `content-visibility: hidden`**（dsh 0.1.7 的逐项显形优化）：卡片在其下不可见/不懒加载是宿主的渲染优化语义，不是本插件的兼容破坏；灯箱若在折叠瞬间打开会随宿主显形逻辑消失/复现，行为可接受，不针对它做反制。
- **dsh 0.1.7 手风琴的交互变化**（工具调用默认折叠）对卡片触达率的影响：属宿主产品决策，观察不动作。

## 4. 兼容口径变化

- 已验证矩阵从 0.1.6-alpha.2 扩到 **0.1.7-alpha.1**（真机会话全量体检 + 挂载冒烟）；peer 依赖维持 `>=0.1.5-rc.2` 不变。
- 卡片灯箱不再依赖宿主 DOM 结构假设（top layer），对后续宿主样式演进免疫。
- `/api/job` 增 `session` 参数（向后兼容：缺省取最近一条）；`/api/state` 的 renders 项增 `sessionId` 字段（旧消费方无感）。
- 任务簿跨重启回放后，「宿主重启后任务簿清空」的旧口径作废——总览页空态文案同步修改；卡片侧「不可达」降级提示只在真不可达（服务挂了）时出现。
