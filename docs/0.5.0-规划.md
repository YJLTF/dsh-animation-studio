# 0.5.0 版本规划：配音落地、工具产出打磨与表达力扩面

> 0.1.0 打通「模型 → AnimationSpec IR → MP4」全链路，0.2.0 把工作台「亮出来」，0.3.0 把图层类型从 4 种撑到 13 种并补上资产管线与导演 preset，0.4.0 把产能做厚（增量渲染、实例常驻、音轨/字幕/退场）。
> 0.5.0 的主题是**兑现**：把前四个版本一路挂账到「0.5」的东西逐一兑现——0.1 就在 IR 里预留的 TTS 配音、0.4 真机挂起的 jobs 后台化、0.4 §4.8 让路完毕的打字机与 video 图层；同时把「模型 ↔ 工具」配合再打磨一轮：回执更丰富（批量读取、时间线摘要、单幕直放）、纠错更前置。四条主线：
> 1. **清账**：遗留问题逐条盘点处置，每条给出去向（落地 / 评估后销账 / 正式放弃），不留悬账；
> 2. **配音**：TTS 语音合成落地——Provider seam + 外部命令通道（edge-tts / piper 配方），旁白 cue 从「显示」升级为「发声 + 显示」，音画对齐以「报告 + 缓存」落地；
> 3. **稳与丰**：工具产出稳定性与丰富性——`anim_get` 批量与摘要视图、单幕预览直放、渲染回执拼贴图、写库纠错持续收敛；
> 4. **表达力**：元素与属性扩面——video 图层、文本段落排版与逐字打字机、lineDash、渐变填充、缓动 in/inOut 变体。

## 2. 主体 A：遗留清账与真机基线（M0）

### 2.1 jobs 后台化真机调查（§1.1 #1）

- 真机排查 dsh-tool-jobs 的加载路径：它是否需要宿主 profile 显式启用、能否经 preset/宿主组合让插件上下文拿到 `ctx.jobs`；顺带核对 0.1.6-alpha.2+ 是否已变化；
- 代码面已就绪（opRender/opPreview 同一降级链、BackgroundTicket/PreviewTicket、任务簿 `/api/state`），**本项零插件代码改动**——结论只有两种：能启用 → 真机验收后台票据全链路（进度条、job_output 收集、job_kill 终止）；不能启用 → 结论落档本文件，同步回退正式定性为「当前部署的设计内形态」，README 表述刷新；
- 附加产出：同步路径下「模型回合被渲染挂住」的实测时长记录（为 §2.4 的 loopback 评估提供对照数据）。

### 2.2 面板音频试听（N1 的另一半，低成本）

- `MEDIA_TYPES` 补 `.mp3/.wav/.ogg/.m4a/.flac`（MIME 表齐全即可，放行规则不变：outputDir 内或回执精确路径 + 白名单）；
- AssetCard：audio 资产给 `<audio controls>`（source 走 `/dsh-anim/media?p=`）；RenderCard：成片卡已有 `<video>` 自带播放，补「音轨清单」展示（`audioTracks` 字段已贯通）；
- 冒烟：MIME 表断言（音频扩展可达 + 可达扩展的 Content-Type 正确）。

### 2.3 真机基线复验（开工第一件事）

沙箱无浏览器，渲染侧一切改动的对照基线沿用 0.4 的结论数字（冷 24.6s / 暖 15.2s / 增量 8.2s / 全命中 0.1s）。本版本开工时在 dsh 0.1.6-alpha.2+ 复跑一遍 examples 全链路出片，确认基线数字未漂移；漂移则先归因再动工。

### 2.4 loopback RPC 直改 spec：评估销账（§1.1 #5）

- 测量：真机走一遍「面板按钮 → session/prompt → 模型回合 → anim_patch 落库」全链路，记录端到端延迟与 token 消耗；
- 判据：延迟秒级内且 token 成本可忽略 → **正式销账不做**（「模型是唯一写者」保证 coerce/对账/事件语义单一出口，简单性价值高于延迟收益），结论记进本文件；延迟不可接受 → 落「撤销这步」单按钮直改 PoC（undo 是唯一无歧义、无需 coerce 的操作），其余按钮维持 followup；
- 无论结论如何，本项在 0.5.0 内闭环，不再挂账。

## 3. 主体 B：工具产出的稳定性与丰富性（稳·丰）

### 3.1 `anim_get` 批量读取 + 摘要视图（N1）

- **批量**：schema 增 `paths: string[]`（与单 `path` 并存，单数形式向后兼容），回执按 path 分段返回，单段截断口径与现状一致；一个来回拿齐「图层 + 资产 + theme」；
- **摘要**：`view: 'summary'` 返回时间线摘要——各幕 `{id, startMs, durationMs, 图层数, 音频图层}`、全片总时长、narration cues 数、资产清单（id/kind/引用计数）；模型做「节奏体检复查」「删资产前的引用检查」不再需要拉整段 JSON；
- 摘要由 spec 包新增纯函数产出（store 与 client 面板可复用同一份）；冒烟：批量多段返回 / 摘要字段口径 / 单数形式兼容。

### 3.2 单幕预览直放（N2）

- 「预览这一幕」按钮与 `anim_preview` 增加段缓存快路径：目标幕的段文件存在且指纹命中 → 直接把段 mp4 走媒体路由内嵌播放（原画质、带音频），卡片从 FrameGrid 升级为 VideoPanel；
- 未命中（无段缓存 / 指纹失配 / 无渲染产物）回退现有抽帧路径，预期管理表述不变；
- 段缓存是渲染副产品，此能力**零新增渲染开销**——只是把已有的东西送到面板；
- 边界：段文件与现行渲染参数（fps/scale/分辨率）不一致时不得直放（指纹已含渲染参数，天然覆盖）。

### 3.3 渲染回执拼贴图（contact sheet）

- `anim_render` 收尾按幕均匀抽 4~8 帧拼成一张 contact sheet（ffmpeg tile 滤镜，落 `outputDir/<specId>/contact-<hash>.jpg`），回执与卡片带路径；
- 价值面：模型回执可见「成片结构是否对」（幕序、留白、字幕带占用），用户在面板一键看到全片概览——补上「渲染完成 → 只能逐帧翻 preview」的空档；
- 拼贴失败只降级警告（不出片失败），不阻塞渲染回执；文件命名带内容 hash，重渲自然覆盖不堆积。

### 3.4 纠错对照表进 preset + coerce 持续收敛（N3）

- preset persona 增「高频手误对照」段：ease 字符串 / type 大小写 / strokeWidth 别名 / color 别名 / 字幕带占用 / atMs 全片绝对毫秒口径等已收编错形的「错误写法 → 规范写法」对照表；冒烟锚点校验沿用既有模式；
- coerceScene / 别名表按真机新错形按需扩充（0.5 候选：atMs 秒-毫秒量级混淆的软警告、十六进制颜色缩写归一）——原则不变：只修无歧义、不丢内容的错，repairs 随回执回报；
- 工具描述与 preset 的口径由冒烟断言钉住（描述示例可解析、可过校验、codegen 零警告的既有断言扩展到对照表）。

## 4. 主体 C：元素与属性扩面（广）

### 4.1 文本段落排版（低成本，真机经验直接复用）

- text 图层静态属性增 `maxWidth` + `textWrap`（MC Txt / Layout 原生 signal，直通 STATIC_PROPS 即生效）——正文长段落自动折行，不再只能靠模型手工断句；
- 0.4 字幕折行趟过的两个坑直接复用为已知约束：`\n` 需要 `textWrap:'pre'` 才生效、`lineHeight` 数字语义是 px（倍数传字符串）——写进工具描述与 preset 对照表；
- 冒烟：STATIC_PROPS 扩展 + 折行生成物断言。

### 4.2 lineDash 直通与渐变填充（P1）

- line/arrow 增 `lineDash`（MC Curve 内建 signal，直通）——虚线/辅助线的教学表达；
- `fill` 支持渐变描述对象：`{ type:'linear', from:[x,y], to:[x,y], stops:[[offset,color],…] }`（或 MC 实际 API 形态为准，**真机核实 MC 3.17 的 LinearGradient 构造签名后定稿**），codegen 把对象翻译成渐变实例；不支持渐变的属性位维持现状告警降级；
- 真机首验：渐变在 rect/text/code 的观感与 headless 出帧稳定性；验证不过则本项缩回 lineDash 单独落地，渐变顺延并落档。

### 4.3 逐字打字机 reveal（0.4 §4.8 让路完毕）

- text 图层 `props.reveal` 轨道（0→1）由 codegen 特判：生成按进度裁剪文本的 signal（复用字幕折行已验证的文本度量路径），实现逐字/逐词浮现；
- 与配音（§5）天然搭配：旁白发声 + 逐字出现是教学片的标准形态；
- 文本度量风险沿用 0.4 收口时的判断：涉及估宽，先做**字符数近似**（CJK 等宽假设），真机验收形态不达标再上精确度量；
- 冒烟：reveal 轨道生成物断言（普通文本轨道不受影响）。

### 4.4 video 图层（0.4 §4.8 到期，真机验证 gate）

- asset kind 增 `video`（`anim_asset_import` 白名单与 copyAssetsToPublic 跟随）；图层 `type:'video'`，props：`src`（`asset:<id>`）、`volume`、`loop`——映射 MC Video 节点；
- **唯一硬门槛是真机验证**：headless 导出下 Video 节点的帧同步（MC 3.17 有 Video 节点但 headless 出帧行为未验证）。M2 开工首日验证，不过则整项顺延 0.6 并落档原因，不做半吊子；
- 验证通过后：STATIC_PROPS/COMPONENT/ANIMATABLE_BY_TYPE 三表 + 工具描述 + preset 同步（三表 Record 类型钉死，漏改编译期就炸）；音视频混合时间线的预期管理写进描述（实拍片段与动画时间轴的对齐口径）。

### 4.5 缓动 in/inOut 变体（低成本）

- `EaseSpec` 增 `bounceIn/bounceInOut`、`elasticIn/elasticInOut`、`backIn/backInOut`，映射 MC 对应导出（0.4 的「映射表 × MC .d.ts 实际导出」静态断言模式照搬，防升级漂移）；
- `coerceScene` 的 ease 字符串包装对新品类自动生效；工具描述与 preset 对照表同步。

### 4.6 chart 图层评估（P2，评估制）

- 教学片高频需求（数据讲解、对比图表），但复合图层的历史结论是「preset 配方教学覆盖」——0.5 只做**评估**：最小范围（bar/line 两种，`data` 数组 + 自动坐标轴 + 数值动画入场）的真机 PoC，评估「codegen 生成量、MC 实现路径（Rect/Line 组合 vs 第三方）」；
- PoC 立住 → 正式入 IR 排 0.6（本版本不进稳定面）；立不住 → 销账「不做」，维持 preset 配方路线（用 rect 轨道摆柱状图的技巧进 §4.7 技巧包）。

### 4.7 视频技巧包更新（零代码）

## 5. 主体 D：配音 TTS（本版本头牌）

### 5.1 架构原则：Provider seam，宿主外置

- TTS 能力是与渲染 seam 同构的标准接口：`TtsProvider`（`synthesize(text, opts) → { filePath, durationMs }`）+ 注册表 + `provideTts()`——想接云服务/本地引擎就写一个 Provider 顶掉默认项，工具与 IR 零改动；
- **首发不内置任何云 SDK / API key**：默认 Provider 是「外部命令」通道——配置模板 `tts.command`（占位符 `{text}` `{outFile}` `{voice}` `{rate}`），进程执行、产物落盘、ffprobe 实测时长；edge-tts（免费、需网络）与 piper（完全离线）作为 README 配方，契合离线分发定位；
- `anim_diagnose` 增 TTS 报告：命令是否配置、可否执行（dry-run 探测）、缓存放；未配置时报告「字幕照常、无配音」的设计内形态。

### 5.2 IR 最小增量

- `narration` 增可选 `tts?: { voice?: string; rate?: number; volume?: number }`（全片默认）；cue 级 `voice` 字段 0.1 起已预留（`types.ts:264`），本版本接通消费，cue 可覆盖默认 voice；
- **语义不变式**：TTS 关闭时 IR 渲染结果与 0.4 完全一致（`tts` 缺省即纯字幕模式）；`subtitles` 字段维持预留不动；
- spec `version` 仍为 1（增量全为可选字段，存量 spec 天然兼容）。

### 5.3 渲染接线与缓存

- 渲染入口发现 `narration.tts` 且 Provider 可用 → 逐 cue 合成：缓存键 = 稳定序列化（text, voice, rate）的 hash，产物落 `work/<specId>/tts/<hash>.<ext>`——同文重渲零重合成（段缓存同款纪律）；
- 合成产物实测时长（ffprobe）加入音轨清单：起点 = cue 的全片绝对 `atMs`，与 BGM/audio 图层同一 mux 管线（`adelay` 对齐 + `amix`，0.4 M2 已验证多轨混音）；
- 字幕显示时长跟随实测音频：`cue 展示时长 = max(估算时长, 实测音频时长)`——避免「字没了声还在」；语音溢出进下一幕起始时间的冲突给软警告（点名 cue 与毫秒数）；
- **音画自动对齐 v1 口径：报告而非改时间线**——渲染回执带每条 cue 的 `{ text, atMs, audioMs, 溢出 ms }` 清单，需要挪时间/改文案由模型 `anim_patch` 决策。自动伸缩场景时长明确不做（时间线是模型的领地，自动改会破坏指纹、大纲对账与增量缓存的语义）。

### 5.4 失败与降级（红线不变）

- 单条 cue 合成失败：该条降级为纯字幕 + 警告进回执与事件，**不阻塞出片、绝不静默**；
- 命令整体不可用（未配置/执行失败）：全片降级纯字幕模式 + 一条汇总警告；
- 隐私说明写进 README 与 `anim_diagnose` 报告：TTS 会把旁白文本送进配置的外部命令（可能出网），离线环境用 piper 类本地引擎。

### 5.5 真机验收

- edge-tts 配方端到端：中文旁白出片有人声、音画对齐（adelay 起点准确）、字幕跟随语音时长、二次渲染缓存命中不重合成（耗时对照落档）；
- 失败注入：坏命令 / 超时 → 降级警告可见、成片照常；
- piper 离线配方至少文档级验证（沙箱装不了则真机补验并记档）。
